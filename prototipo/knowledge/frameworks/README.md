# Marcos teóricos de fondo (el "porqué" de las herramientas)

Estos documentos NO son herramientas paso a paso (esas están en `conocimiento/herramientas/`).
Son los **fundamentos teóricos** de las metodologías de la Ruta DIA. Úsalos para EXPLICAR el porqué
de una herramienta o profundizar en una metodología. NO inventes conceptos: cita de cuál marco sale.

| Archivo | Metodología | Dónde aplica en la Ruta DIA |
|---|---|---|
| `design_thinking_handbook.md` | Design Thinking (6 fases) | Descubrimiento (empatía, observación, definición) e Incubación (ideación, prototipado). Sustenta mapa de empatía, customer journey, arquetipo, árbol de problemas. |
| `design_thinking_tim_brown.md` | Design Thinking (mentalidad) | Transversal a Descubrimiento + Incubación. Marco conceptual: deseabilidad/factibilidad/viabilidad, divergente↔convergente, prototipar para aprender. |
| `jobs_to_be_done.md` | Jobs to Be Done (Christensen) | Descubrimiento (etapas 1–4): entender el "progreso" real que busca el usuario. Sustenta mapa de empatía, arquetipo y la definición del reto. |
| `disciplined_entrepreneurship.md` | Disciplined Entrepreneurship / complementa Lean Startup | Incubación (etapas 6–8: modelo de negocio, propuesta de valor, hipótesis) y Aceleración (etapas 9–10: MVP, validación de demanda, escalar). Sustenta lean canvas, canvas de propuesta de valor, ficha de hipótesis. |
| `sit_manual.md` | **SIT (Systematic Inventive Thinking)** — 3ª metodología de la Ruta DIA | Ideación (etapa 4). Manual de coach: los patrones de innovación estructurada. A diferencia de Design Thinking, NO parte del usuario sino del sistema/producto que ya existe. Sustenta la ficha `herramientas/sit.md`. |
| `lean_startup.md` | **Lean Startup (Eric Ries)** — 2ª metodología de la Ruta DIA | Alistamiento e Incubación (etapas 5–8): construir–medir–aprender, MVP, métricas accionables, pivotar o perseverar. Sustenta ficha de hipótesis y la tabla de experimentación. |
| `design_sprint.md` | Design Sprint (Knapp, Zeratsky, Kowitz) | Incubación (etapas 6–7): proceso de 5 días para pasar de problema a prototipo probado con usuarios. Formato intensivo para diseñar y ejecutar un experimento. |
| `scrum.md` | Scrum (Jeff Sutherland) | Ejecución iterativa: sprints, roles y ceremonias. Aplica al *cómo se organiza el equipo* durante Incubación y Aceleración, no a una etapa concreta. |
| `how_to_future.md` | Futuros / foresight (Smith & Ashby) | Transversal, útil al definir el reto (etapa 1) y al escalar (etapa 10): pensar en múltiples futuros posibles en vez de uno solo. |

> Ojo: `marcos/sit_manual.md` es el **fundamento** de SIT; `herramientas/sit.md` es la ficha corta de
> "cómo se usa". No los confundas: para explicar el porqué, el manual; para guiar el paso a paso, la ficha.
